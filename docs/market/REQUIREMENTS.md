## 1. 项目概述

### 1.1 背景

- 本人为数据科学与大数据专业大三学生，已有工程型项目 **SeenYou**（Python 桌面工具：ADB + OCR + 多线程 + 告警推送），证明工程落地能力。
- 现有简历缺少能证明**数据科学全流程能力**（获取 → 存储 → 清洗 → 分析 → 建模 → 可视化）的项目，与专业方向不匹配。
- 本项目用于补齐这一缺口，并**直接服务于求职**：产出真实、可复现的招聘市场洞察。

### 1.2 项目目标（SMART）

1. 采集 **≥ 5,000 条**真实招聘岗位数据（覆盖 10 个城市 × 5 类岗位，量纲口径见 4.4），存入 MySQL。
2. 完成**可复现**的数据清洗与 EDA，产出 **≥ 6 个图模块**的可视化分析与 **≥ 5 条**可写进简历的行业洞察（口径见 5.4 / AC-4）。
3. 构建**薪资预测模型**（XGBoost 回归，实习岗默认不混入全职建模集），验收标准：测试集 **R² ≥ 0.50**（降级路径见 R4）。
4. 交付**交互式看板**（单 HTML，数据内嵌，无需服务端即可打开筛选）与分析报告。
5. 支持**增量更新**（基于 job_snapshots 快照表累积历史，见 REQ-DB-04），数据随批次增长可做时间趋势分析（加分项）。

### 1.3 项目定位

- **一句话定位**：爬取真实招聘数据 → 清洗建库 → 分析岗位市场规律 → 预测薪资 → 交互看板展示，形成数据科学全流程闭环。
- **与 SeenYou 的关系**：互补。SeenYou 证明工程能力，JobPulse 证明数据能力；SeenYou 的工程素养（重试、日志、容错）在本项目延续。

### 1.4 目标用户

- 主要用户：本人（求职决策参考 + 简历素材）。
- 演示用户：面试官（看板、报告、GitHub README）。

## 2. 术语表

| 术语 | 含义 |
|---|---|
| JD | 职位描述（Job Description），岗位详情中的文本 |
| P0 / P1 / P2 | 需求优先级：必须 / 应该 / 可选加分 |
| ETL | 抽取-转换-加载（清洗转换流程） |
| 兜底数据源 | 当主爬源不可用时的备用公开数据（GitHub 开源数据集，选取标准见 4.1 / REQ-DC-06） |

| 幂等 | 同一记录重复抓取/写入不产生重复数据 |
| adapter | 数据源适配器：在统一接口下按数据源实现解析与字段映射的插件式模块（见 4.1） |
| UA 池 | 预置多组 User-Agent 请求头列表，请求时随机轮换以模拟正常访问（见 REQ-DC-02） |

| checkpoint | 本地持久化的采集进度记录文件，用于断点续爬（见 REQ-DC-04） |

| 岗位性质 | 实习 / 校招 / 社招 / 不限（见 4.2 `job_type` 字段） |

### 3.1 数据范围

| 维度 | 范围 |
|---|---|
| 城市 | 北京、上海、广州、深圳、杭州、成都、南京、武汉、西安、苏州（10 城） |
| 岗位关键词 | 搜索用关键词：数据分析、数据分析师、数据科学、大数据开发、大数据工程师、算法工程师、机器学习、BI工程师、数据仓库（映射到 5 大类，见 11.2；关键词与大类名可能同词，以 11.2 映射表为唯一依据） |
| 岗位性质 | 实习 + 校招/社招均采集，以 `job_type` 字段区分（见 4.2）；实习与全职分开统计与建模（见 4.3 规则 7） |
| 时间 | 抓取时源端仍在招聘有效期内的岗位；增量采集时发现已下架/失效的岗位按 REQ-SCHED-03 失效标记流程处理 |
| 数据源 | 主爬：51job（一期，P0）；BOSS直聘移动端 API（二期，P1 尝试项，合规边界见 4.1）；兜底：GitHub 公开招聘数据集 |

### 3.2 明确不做（Out of Scope）

- ❌ 不做需登录/需权限的敏感数据抓取（如候选人信息、简历数据）。
- ❌ 不做实时在线服务 / 上线部署（本项目为个人学习与展示，本地运行即可）。
- ❌ 不做分布式爬虫 / 大数据框架（Spark/Flink 等留待后续项目）。
- ❌ 不做招聘平台逆向破解、绕过验证码、大规模并发压测。**若 BOSS 移动端 API 的接入必须依赖逆向签名/脱壳等行为，则放弃该源**（见 4.1），以 51job + 兜底源保证主线。
- ❌ 不承诺数据绝对准确，分析结论为市场趋势参考，非投资/择业唯一依据。

## 4. 数据需求（Data Requirements）

### 4.1 数据源设计

| 数据源 | 角色 | 说明 | 优先级 |
|---|---|---|---|
| 51job（公开搜索接口） | 主爬（一期） | 反爬相对宽松，先打通全链路；W1 需验证搜索接口可稳定分页取数与 post_date/城市字段可得性（见 4.2 字段说明 / WBS W1 验证项） | P0 |
| BOSS直聘（移动端 API） | 主爬（二期，尝试项） | 数据字段全（薪资/经验/学历/公司规模/JD），反爬较强；接入前先评估签名获取方式，若需逆向则放弃该源，不阻塞主线 | P1 |
| GitHub 开源招聘数据集 | 兜底 | 主/备爬均失效时保证项目可继续；选取标准：含城市与薪资字段、更新时间较近、许可证允许个人学习使用（字段映射模板见 11.4） | P0 |

**开发顺序（已确认 2026-02）**：一期 51job 打通全链路 → 二期尝试接入 BOSS，若不可行则维持 51job + 兜底双源，不影响验收主线。

### 4.2 统一数据 Schema（jobs 表 + job_snapshots 表）

> 所有数据源解析后统一转换为以下字段；`source` 字段记录来源。
> `jobs` 表只保留每个 job_id 的最新状态；`job_snapshots` 表按（job_id, crawl_date）追加历史状态，供时间趋势分析（REQ-EDA-04）。

**jobs 表字段：**

| 字段 | 类型 | 说明 | 是否必填 |
|---|---|---|---|
| job_id | VARCHAR(64) | 幂等唯一键 = 源标识 + 原始 ID（如 `boss_123456`）；兜底数据集无原始 ID 时按 `源标识_序号` 生成 | ✅ |
| job_title | VARCHAR(128) | 职位名称 | ✅ |
| job_category | VARCHAR(32) | 归一化岗位大类：`数据分析`/`数据科学`/`大数据`/`算法`/`BI数仓` | ✅ |
| job_type | VARCHAR(16) | 岗位性质：`实习`/`校招`/`社招`/`不限`（解析自标题/标签/详情；无法判定为 `不限`） | ✅ |
| company_name | VARCHAR(128) | 公司名称 | ✅ |
| industry | VARCHAR(64) | 行业（归一化；低频值 < 50 条归为 `其他`，阈值见 REQ-DQ-02） | ✅ |
| company_size | VARCHAR(32) | 公司规模（映射为有序桶，见 11.5） | ⭕ |
| city | VARCHAR(32) | 城市（统一去掉"市"后缀；`苏州工业园区` 等变体归并为所属城市，见 REQ-DQ-02） | ✅ |
| salary_raw | VARCHAR(64) | 原始薪资文本（如 `15-25K`、`面议`） | ✅ |
| salary_min | INT | 月薪下限（元/月，清洗后；面议/缺失/解析失败为 NULL） | ⭕ |
| salary_max | INT | 月薪上限（元/月） | ⭕ |
| salary_avg | INT | (min+max)/2，建模目标变量 | ⭕ |
| experience_req | VARCHAR(32) | 经验要求（归一化枚举，见 11.5） | ✅ |
| education_req | VARCHAR(32) | 学历要求（归一化枚举，见 11.5） | ✅ |
| job_desc | TEXT | JD 全文（技能图谱输入） | ✅ |
| tags | JSON | 职位标签（如 `五险一金`、`周末双休`；源端无标签时为空数组） | ⭕ |
| post_date | DATE | 发布日期（如可得；W1 需验证 51job 是否提供，不可得则留空并计入缺失率） | ⭕ |
| crawl_date | DATETIME | 抓取时间（增量更新依据） | ✅ |
| url | VARCHAR(255) | 原始链接 | ✅ |
| is_valid | TINYINT | 是否有效（默认 1；含异常薪资/重复/增量时发现下架的岗位标记为 0，见 REQ-SCHED-03） | ✅ |
| source | VARCHAR(16) | 数据源标识（job51 / boss / backup） | ✅ |

> 说明：`skills_hit` / `skills_count` 为模型特征，由 REQ-NLP-05 产出并写入 `output/analysis/features.parquet`（中间产物，不入 jobs 表），避免技能词表变动引发全表重建。

**job_snapshots 表字段（REQ-DB-04）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT AUTO_INCREMENT | 主键 |
| job_id | VARCHAR(64) | 与 jobs.job_id 对应 |
| crawl_date | DATETIME | 本次抓取时间（与 jobs.crawl_date 同批次值） |
| salary_min / salary_max / salary_avg | INT | 当次清洗后薪资 |
| is_valid | TINYINT | 当次有效状态（含下架标记） |
| url | VARCHAR(255) | 当次链接（可选） |

> 唯一索引：`UNIQUE (job_id, crawl_date)`。同一批次内同一 job_id 只写一行（批次内先去重）。
> Schema 变更策略：新增列/表通过 `src/storage/migrations/` 下按序执行的迁移脚本管理（增量演进，不重建现有数据）。

### 4.3 薪资归一化规则（P0，清洗模块核心）

1. 单位统一：`K` = 千元/月；`万/年` ×12 换算为月；`元/天` 按 21.75 天换算为月（**实习岗除外**，见规则 7）。
2. 区间 `min-max` → salary_min / salary_max；单值 `x` → min=max=x。
3. 中文单位：`5千-8千`、`1万-2万` 按千/万换算为元。
4. 含"薪"数年薪：`15-25K·14薪`、`30-50万/年` 等 → 先换算为月薪再取 min/max；无法解析"薪"数时按 12 薪处理并记日志（计入"未知格式"统计）。
5. `面议` / 缺失 / 解析失败 → 各薪资字段为 NULL，**保留记录但不进入建模集**；解析失败另记日志并计入数据质量报告。
6. 异常值：salary_max > 300,000（月薪 30 万+）或 salary_min < 1,500（低于主要城市最低工资参考线）或 salary_min > salary_max → 标记 is_valid=0 并记日志（视为数据错误或虚假信息）。
7. **实习岗**（job_type=实习）按 `元/天` 计薪时：折月薪 = 日薪 × 20（约 5 天/周 × 4 周），**不乘 21.75**（避免高估）；实习薪资在数据质量报告中单列统计；实习岗可参与 EDA，但默认不进入全职建模集（见 REQ-ML-01/02）。
8. 未知格式 → 薪资字段置 NULL，记日志并计入"未知格式"统计（数据质量报告输出）。
9. 规则全部沉淀为**纯函数 + 单测**（每条规则 ≥ 1 个用例），保证可复现。

### 4.4 数据量目标

| 指标 | 目标 | 口径说明 |
|---|---|---|
| 有效记录总数 | **≥ 5,000 条**（is_valid=1） | 以 jobs 表最新状态计数 |
| 单城市最少记录 | ≥ 200 条 | 10 城均可比 |
| 单岗位大类最少记录 | ≥ 600 条 | 保证"5 类全覆盖"可判定；某类不足时优先扩展关键词，仍不足则在报告中声明并靠兜底数据集补充 |
| 可建模记录（薪资非空） | ≥ 3,500 条 | 建模集（全职为主，实习单列） |
| 去重率 | 按 job_id 幂等，重复抓取 0 新增重复 | jobs 表不增行；job_snapshots 按批次追加（见 REQ-DC-03） |

## 5. 功能需求（Functional Requirements）

> 优先级：**P0** = 必须（影响主线交付）；**P1** = 应该（提升完整度）；**P2** = 可选加分（有余力再做）。
> 异常处理总原则：任一模块失败不阻断主流程（NFR-01）；单条数据异常跳过并记日志，不中断批次。

### 5.1 数据采集模块（REQ-DC）

| 编号 | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| REQ-DC-01 | 爬虫支持 10 城 × 5 类岗位关键词组合采集 | 可配置城市/关键词列表，单次运行按配置执行 | P0 |
| REQ-DC-02 | 反爬容错：随机延时（2~5s）、UA 池、请求重试（3 次，指数退避） | 断网/超时/限流（429/5xx）时重试且不崩溃，日志记录失败项；**403/验证码/封禁不重试**，立即停止该源并输出告警（见 REQ-DC-07） | P0 |
| REQ-DC-03 | 增量采集：按 job_id 幂等写入；已存在记录更新 jobs 表最新状态，并每次抓取追加一条快照到 job_snapshots 表 | 对同一源重复运行两次，jobs 表记录数不增加，job_snapshots 记录数按批次增加 | P0 |
| REQ-DC-04 | 断点续爬：以本地 checkpoint 文件记录每个 城市×关键词组合 的已完成页码/游标 | 中断后重跑从 checkpoint 处继续，不从头开始；job_id 仅用于去重，不用于进度恢复 | P1 |
| REQ-DC-05 | adapter 模式：至少 2 个源可插拔 | 切换 `--source boss/job51/backup` 参数即可切换数据源 | P0 |
| REQ-DC-06 | 兜底源导入脚本（GitHub 数据集 → 统一 Schema） | 一条命令完成导入；交付字段映射清单（模板见 11.4）与数据集许可证声明 | P0 |
| REQ-DC-07 | 采集健康监控：按 城市×关键词组合 统计请求成功数/命中数/失败数 | 运行结束输出采集统计表；任一组合 0 命中或整体命中率 < 30% 时输出告警日志 | P1 |

|---|---|---|---|

### 5.3 清洗与数据质量模块（REQ-DQ）

| 编号 | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| REQ-DQ-01 | 薪资归一化（规则见 4.3） | 规则为纯函数且有单元测试覆盖（4.3 规则 1~9 各 ≥ 1 个用例） | P0 |

| REQ-DQ-03 | 缺失率统计报告：每字段缺失率、面议比例、异常薪资占比、未知薪资格式数、实习薪资单列统计 | 运行产出 `output/data_quality_report.md`，含报告生成时间与数据量 | P0 |

### 5.4 探索性分析（REQ-EDA）

> 图模块口径：REQ-EDA-01~03 的产出合计构成 ≥ 6 个图模块（分布类 ≥ 3、对比/相关性类 ≥ 3，另可选趋势类），AC-4 以图模块清单勾验；"张"为图文件数，模块清单以本节为准。

| 编号 | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| REQ-EDA-01 | 岗位市场分布：城市 × 岗位量、岗位大类分布、行业分布 | 产出 ≥ 3 张图（matplotlib，中文可显示） | P0 |
| REQ-EDA-02 | 薪资洞察：学历-薪资、经验-薪资、城市-薪资、岗位类别-薪资（实习/全职分开统计） | 产出箱线图/折线图/热力图 ≥ 3 张，均带结论 | P0 |
| REQ-EDA-03 | 分析结论沉淀：每张图对应一段文字洞察，汇总进报告 | 报告含 **≥ 5 条**可写进简历的量化结论（每条须含具体数值与统计口径，如"样本 N、均值/中位数"） | P0 |

## 7. 技术架构

### 7.1 架构总览（分层）

```
┌─────────────────────────────────────────────────────┐
│ 交互层：ECharts 看板（HTML） / 分析报告（MD）        │
├─────────────────────────────────────────────────────┤
│ 分析层：EDA（pandas/matplotlib） + 技能图谱（jieba） │
│         + 薪资预测（XGBoost/scikit-learn）          │
├─────────────────────────────────────────────────────┤
│ 数据层：ETL 清洗与质量（纯函数 + 单测）              │
│         SQLAlchemy ORM → MySQL（SQLite 开发兜底）    │
├─────────────────────────────────────────────────────┤
│ 采集层：adapter 模式（boss / job51 / backup）        │
│         重试 + 限速 + UA 池 + 幂等写入 + checkpoint  │
└─────────────────────────────────────────────────────┘
```

### 7.2 技术选型

| 环节 | 选型 | 备注 |
|---|---|---|
| 语言 | Python 3.10+ | 本机 3.13 |
| 采集 | requests / httpx | 同步即可，无需 asyncio 复杂度 |
| 存储 | MySQL 8.x + SQLAlchemy 2.x | SQLite 作开发兜底 |
| 清洗分析 | pandas / numpy | — |
| 文本 | jieba + 自定义词典 | 词云用 wordcloud（需中文字体） |
| 建模 | scikit-learn + XGBoost | 若 py3.13 安装受阻，备选 lightgbm |
| 可视化 | matplotlib（静态图）+ ECharts（交互看板） | 图需解决中文显示 |
| 调度 | APScheduler（可选）/ 手动命令 | P1 再引入 |
| 工程 | logging、pytest（单测）、git、requirements.txt | — |

### 7.3 目录结构（约定）

```
jobpulse/
├── docs/                    # 需求文档（本文件）
├── src/
│   ├── cli.py               # 命令行入口：crawl / etl / analyze / model / viz / import-backup / check-env
│   ├── crawler/             # 采集：adapter（boss/51job/backup）+ 反爬 + checkpoint
│   ├── storage/             # SQLAlchemy models（jobs/job_snapshots）、session、建表
│   ├── etl/                 # 清洗纯函数 + 数据质量报告
│   ├── analysis/            # EDA 脚本（每图一个脚本或 notebook）
│   ├── nlp/                 # 分词、技能词表、技能覆盖
│   ├── model/               # 特征工程 + 训练评估 + 特征重要性
│   ├── viz/                 # 看板数据 JSON 生成 + HTML 模板
│   └── scheduler/           # 增量调度（P1）
├── data/                    # 中间产物 + checkpoint 文件（.gitignore，不入库）
├── output/                  # 图表、report.md、看板 HTML、features.parquet（入库展示）
├── tests/                   # 单测（清洗规则、幂等、快照）
├── config/                  # 配置（DB 连接、城市/关键词、延时/重试、技能词表 skill_words.json）
├── requirements.txt
├── run_all.py               # 一键链路入口（AC-1：check-env → 建库 → 采集 → 分析 → 出报告）
└── README.md
```

### 7.4 配置管理

- `config/config.yaml`（或 JSON）：数据库连接、城市/关键词列表、延时/重试参数、命中率告警阈值、技能词表路径、兜底源路径、checkpoint 目录。
- 敏感信息（DB 密码）通过环境变量或 `.env`（不入 git），config 中引用占位符。

## 10. 风险与应对

| # | 风险 | 影响 | 应对 | 触发条件/缓解 |
|---|---|---|---|---|
| R1 | 目标网站反爬封禁 | 采集中断（P0 链路） | 限速 + UA 池 + 重试退避；**403/封禁不重试，立即切换备源/兜底源**并告警；采集分批执行 | 出现 403/封禁 → 降速并切换源 |
| R2 | 数据源页面结构变更 | 解析失败 | adapter 模式隔离解析层；变更时只改对应 adapter | 解析 0 命中 → 检查源结构 |
| R3 | 本机未装 MySQL | 存储受阻 | SQLAlchemy 抽象 + SQLite 开发模式先行；README 给出 MySQL 安装指引 | 环境检查脚本检测 |
| R4 | 薪资缺失/面议比例过高 | 建模集不足 | 统计缺失率；>30% 时补充数据源**或调整建模目标**（如分类为薪资区间），并同步将 AC-6 替换为备选验收（如 R² ≥ 0.45 或分类准确率 ≥ 70%），在模型评估记录中声明 | W2 数据质量报告 |
| R5 | xgboost 与 Python 3.13 兼容问题 | 建模受阻 | 备选 lightgbm / sklearn HistGradientBoosting | W3 安装时报错时切换 |
| R6 | 数据量不足 5,000 | 验收不达标 | 扩展城市/关键词；启用兜底数据集；按 4.4 弹性标准（单类下限）在报告中声明 | W2 中段检查计数 |
| R7 | 中文图表乱码 | 交付物质量差 | matplotlib 统一中文字体配置（SimHei/Microsoft YaHei）；wordcloud 指定中文字体 | 首个图表即检查 |
| R8 | 时间趋势依赖快照批次积累，批次不足 | REQ-EDA-04（P2）无法产出 | P2 不阻塞主线；报告中声明"样本不足"；AC-11 已含降级判定 | W5 检查批次数 |
| R9 | 特征泄漏：目标编码用全量 y、同源复制岗位 | 模型指标虚高、结论失真 | 目标编码在 CV 折内拟合；建模前按 job_id 去重（REQ-ML-01） | W3 特征工程评审 |
| R10 | BOSS 移动端 API 需逆向签名而放弃 | 二期数据源缺失 | 51job + 兜底双源保障 P0；BOSS 仅作 P1 尝试项 | 4.1/3.2 边界确认 |

### 11.6 REQ-NLP-01 人工核对判定清单

- 核对内容：随机抽样 100 条 JD 的分词结果，统计技能词误识别（把非技能词识别为技能词）与漏识别（技能词未命中）。
- 判定标准：技能词误识别率 ≤ 5%（即 ≤ 5 条）；无系统性噪音（同一错误模式反复出现，如"数据"被整体误识别为技能词）。
- 输出：核对记录表（样本 job_id、误识别/漏识别条目、结论）随报告存档。
