## 重要问题（已修订/纳入）

- 技术选型（Q3）建议：前端 **Vite + Vue 3 + TypeScript**，后端 **Node.js + TypeScript + Fastify** + **better-sqlite3**（若更熟 Python 则 FastAPI，接口契约不受影响）；前后端同语言为首要理由。
- 抓取解析（Q8）分层：probe（robots/sitemap/首页/子域）→ ATS 识别 → 适配器（M1 做 Greenhouse/Lever/飞书招聘 + JSON-LD 兜底；北森/Moka/大易归 M2）→ 人工录入兜底；**不引入无头浏览器**。
- 安全基线补三条：CORS 白名单（仅前端来源）、Host 头校验（防 DNS rebinding）、启动生成随机 token 由前端携带。
- 探测+抓取改为**后端异步任务**（立即返回 job_id、前端轮询）；单 HTTP 请求 < 10s、单公司任务 < 60s。
- 岗位补充 job_type（校招/社招/实习）、degree（学历要求）、publish_date（发布日期）字段，支撑秋招筛选核心场景。
- 去重需公司名归一化（去"有限公司/股份"后缀）；4.7 导出加 schema_version；抓取限速量化（串行、同域间隔 ≥1.5s、全局 ≤30 请求/分钟、固定 UA）。
- 4.9 提醒定义去重（同提醒点只触发一次）与错过补发（下次打开站内提示）。
- 4.8 统计口径在 M2 前定义（进行中=非终态且已投递；趋势按 applied_at）。
- "每周自动导出提醒"孤儿需求落实为：应用启动时检查距上次导出 > 7 天则站内提示。
- 风险清单补充：时间/范围风险、SQLite 文件损坏、端口占用、简历打印跨浏览器差异。
